# Outputs of a module documentation review

A completed module slice should leave:

1. accurate item/module Rustdoc;
2. required executable examples;
3. supporting public type/error documentation where needed;
4. focused tests/fixes for any verified defect discovered;
5. package doctest/rustdoc evidence;
6. updated policy/example observations for the scope;
7. progress/audit record;
8. task guide or glossary additions only when they improve cross-item usability.

Not every slice needs a new standalone guide. The primary deliverable is the
callable contract; guides/glossary are added when they reduce navigation or
conceptual ambiguity.
