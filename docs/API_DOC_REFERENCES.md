# References in scientific API documentation

When an API implements a named algorithm/convention whose semantics are not
obvious, cite a stable primary/reference source in module/item documentation or
a nearby design note. The reference should clarify the implemented definition,
not serve as decoration.

Prefer standards, original papers or authoritative mathematical definitions over
blogs. Record version/section when standards evolve. Keep copyright-respecting
summaries rather than reproducing long source passages.

A reference does not prove the implementation matches it; tests/oracles still
provide implementation evidence.
