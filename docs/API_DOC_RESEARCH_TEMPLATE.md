# Experimental/research API documentation template

Research APIs still require precise contracts. "Experimental" is not a
substitute for documentation.

State:

- research objective and implemented mechanism;
- maturity/status and known missing capabilities;
- assumptions and unsupported cases;
- whether outputs are exploratory scores, exact quantities or heuristics;
- determinism/reproducibility;
- evidence available and claims explicitly not established;
- expected API instability.

Examples should demonstrate the implemented mechanism on a small deterministic
fixture and a distinct unsupported/boundary case. Avoid describing a conjecture,
roadmap item or representation skeleton as an implemented execution capability.
