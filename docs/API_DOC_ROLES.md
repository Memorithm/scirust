# Roles of SciRust documentation surfaces

**README**: orientation and stable entry points.

**Quickstart/task guides**: accomplish a workflow with a small set of APIs.

**Architecture/reference**: system boundaries and cross-cutting design.

**Item Rustdoc**: authoritative caller contract for a public Rust item.

**API lexicon**: generated cross-workspace discovery/navigation.

**API example inventory**: observed example coverage and policy scopes.

**Glossary**: recurring conceptual terminology.

**Evidence/audits**: revision-bound qualification, measurements and findings.

**Standards/checklists**: rules for creating/maintaining the surfaces above.

Keeping these roles distinct reduces duplicated prose and stale contradictions.
