# API documentation review principles

- Truth before coverage percentage.
- Implementation/tests before inherited comments.
- Compiler/rustdoc before assumptions about public reachability.
- Executed doctests before claims that examples work.
- Explicit unsupported cases before silent fallback.
- Exact units/shapes/conventions before shorthand.
- Typed errors before string-dependent examples when available.
- Revision-bound hardware/performance evidence before broad capability claims.
- Focused reviewed batches before generated multi-thousand-function prose.
- Open finding before invented semantics when evidence is insufficient.
